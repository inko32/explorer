1. language: rust
2. GUI library: egui
3. dependency: as less as possible.
4. IO backend: GIO. wrapped for futute migration to rust
5. goal: a Windows 8 file explorer for posix, and windows. posix first.
6. rendering: cpu, vulkan, and wgpu.

features:
some windows 8 exclusive features should be abandoned, like "Homegroup" and others. this should be a modern, KDE, posix file manager
the NT security should be simplified to a posix one.


native drag-and-drop, clipboard, IME, file picker, keyboard navigation, accessibility should be featured.

future-theme:
the border should be able to configure the theme. maybe i will consider a windows 7 theme in the future but not now. so the alpha, or bluring machanism should be considered in very early stage
This is a feature of the border module I think.
and, the border theme, you may know the windows 8 developer preview, or other stage of it's development, there were some modern-aero transparent themes. all of them should be considered. I love them all. but not current stage. if basic skeleton is done, the code is not spaghetti, when it's the time when we are free to consider the theme, remind me. but early stage, it's not the time.
KDE theme integration may be considered in the future but not now. keep an eye.
font should be able to configure.
all dimensions should be configurable, even I can have a win98 style if I want.

high-dpi:
this must be considered in very early stage as a modern feature. the photos I gave you for reference.

dark mode:
it's easy but should be considered in early stage, it's a windows 10 feature but windows 8 should have it.
this is a feature of the theme module.

search:
this is not an early feature. but take a note here:
windows search is slow. learn from others.

GIO:
early stage, use the rust-binding of GIO. it's lightweight.
but it should be wrapped. the following four can be used in case needed.
GIO
POSIX
Windows native
Rust-native

rendering:
not an early stage thing. but the final compiled exe should be able to run without too much configuration under wine-linux. not like eden explorer, it's asking me about the wgpu.
Rendering backend:
- CPU: required
- GPU: optional
- wgpu/Vulkan: implementation detail
UI should not know which backend we are using.

future sudo feature on linux:
may consider, or we have completely no /boot access.
this brings: front-end & back-end should be separated.

threading:
copying or similar operations should not make UI stuck.

remember:
file explorer is an OS infrastructure. so everything should be as native as possible, less dependencies, and stable, behave as expected.


in any case you think egui is not suitable for this project, tell me and we consider iced. but we must think a lot before changing. this decision is very important.
